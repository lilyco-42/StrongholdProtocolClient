# agents/ —— 多 AI 并行开发的工作模块登记处

> 本目录的用途：让**同时在这个仓库里干活的多个 AI**互不踩脚。
> 与仓库根的 `AGENTS.md` 分工不重叠 ——
> `AGENTS.md` 说「这个仓库怎么构建、什么算证据」；`agents/` 说「**谁负责哪块、谁写哪些文件**」。

## 为什么要命名空间，而不是一个公共的 agent.md

多个 AI 往**同一个** `agent.md` 里写，本身就会 git 冲突 —— 那就违背了这个目录存在的理由。
所以约定：**一个模块一个子目录，模块只写自己目录里的东西。**

```
agents/
  README.md              ← 本文件：约定 + 登记表（改这里要协调，尽量只追加表格行）
  <模块ID>/
    agent.md             ← 该模块的自我声明：目标、契约、验收
    权限区域.md           ← 该模块的文件权限边界（独占 / 协商 / 禁区）
```

## 登记表

| 模块 ID | 模块名 | 负责人 | 独占目录 | 状态 | 声明文件 |
|---|---|---|---|---|---|
| `p2p-match` | 玩家自由匹配 + 去中心化服务 | Claude (2026-10-06) | `shell/p2p/`、`test/p2p-*.test.js` | 已声明，未开工 | [agent.md](p2p-match/agent.md) |

> 新增一行 = 认领一个模块。改这张表时**只追加行**，不要重排、不要改别人的行。

## 三条硬规矩

1. **不直接推 `main`。** 一律走 `feat/<模块ID>` 分支 + PR。
2. **独占区之外的文件，改动前先看 `权限区域.md` 里是「协商」还是「禁区」。** 协商区的改动必须是**最小 hunk**，
   并且在自己的 `agent.md` 里登记「我改了哪个共享文件的哪一行、为什么」。
3. **两个 AI 改同一个共享文件时，后改的负责 rebase**，不要把冲突丢给对方。

## 怎么认领

复制 `p2p-match/` 的结构，改 `模块ID`，两张表登记进去，然后按 `权限区域.md` 申请 gh 权限。
