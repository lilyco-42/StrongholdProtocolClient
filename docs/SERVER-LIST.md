# SERVER-LIST.md — `GET /servers.json`：服务器把自己的「更多服务器」告诉客户端

> **状态**：草案（2026-10-08），模块 `server-list`。
> **上位规范**：游戏本体的 `docs/DESIGN.md` 是唯一真相；本文只定义**一个它还没有的只读 HTTP 端点**，
> 并明确它**不**碰 WebSocket 协议（DESIGN §8）。冲突时 DESIGN 赢。
> **本文是给两个仓库、三个 AI 共同遵守的接口契约**：游戏本体（`lilyco-42/Stronghold-Protocol`，服务端实现）
> 与客户端壳（`lilyco-42/StrongholdProtocolClient`，消费方）。

---

## 0. 要解决什么

今天的服务器列表是**编译进壳里的常量**（`shell/picker-core.js` 的 `COMMUNITY_SERVERS` + `SEED_VERSION`）。
网友服随时开、随时关，每变一次就要**重发一版客户端**、还要升 `SEED_VERSION` 去追已经装好的老客户端 ——
这条路走不远：一个刚关掉的服，会让所有老客户端的选择页上挂一条连不上的死条目。

客户端的 `COMMUNITY_SERVERS` 注释里已经写了它的设计意图：

> They are *seeded into the editable list* (`K_LIST`), not added to `BUILTIN_SERVERS`: a server that goes dark must be
> something the player can delete for good, and a built-in row cannot be deleted or edited.

**本方案把「播种」从「编译期常量」升级为「运行期从服务器拉」**，同时**完整保留**上面这条设计意图 ——
拉下来的条目一样进 `K_LIST`（玩家可删、删了不回来），只是来源换成了活着的服务器。

一句话：**玩家连上任何一台服，就能从它那儿问到「还有哪些服可以玩」**，不必等我们发新版本。

## 1. 三条不可让步的原则

| # | 原则 | 为什么 |
|---|---|---|
| **P1** | **接口不存在 = 正常情况，静默退回静态列表** | 全网只有我们自己这几台服会实现它。别人（simfun 等私有服）必然 404。404 **不是错误**，是「这台服不知道别的服」。 |
| **P2** | **服务器下发的地址一律不可信** | 内容来自第三方服务器。只当**候选**，仍要玩家自己点进去、仍可删；绝不自动连接、绝不覆盖玩家手填的条目、绝不当 `BUILTIN_SERVERS`。 |
| **P3** | **纯增量**：没有这个接口时，客户端行为与今天逐字节一致 | 见 `agents/server-list/agent.md` 的验收标准。任何「必须联网才能选服」的写法都是回归。 |

## 2. 接口定义

```
GET /servers.json
```

- **方法**：仅 `GET` / `HEAD`（与 `/healthz` 一致，非 GET/HEAD 由现有路由回 `405`）。
- **路径**：根路径下的**单个静态文件式端点**，与 `/healthz`、`/packs/index.json` 同级。
  **不**引入 `/api/` 前缀 —— 上游没有这个命名空间，自己造一个会更突兀（见 §7 备选方案）。
- **鉴权**：无。公开可读，与 `/healthz` 同级。
- **缓存**：`Cache-Control: no-store`（照抄 `server/http/common.js sendJson`；**必须**，否则玩家会锁在旧列表上）。
- **CORS**：**必须**回 `Access-Control-Allow-Origin: *`。理由见 §5 —— 打包客户端是 `file://` /
  `127.0.0.1:47821` 源，跨域读远程服的 JSON 时浏览器**默认会拦**。
- **编码**：`application/json; charset=utf-8`。

### 2.1 响应体（200）

```jsonc
{
  // 必须：格式版本。客户端见到不认识的值就整体忽略（P3：宁缺勿错）。
  // 本文描述的格式是 1。
  "v": 1,

  // 可选：这台服务器自己的可读名字。仅用于日志/提示，客户端可以不用它。
  "name": "lilyco",

  // 必须：这台服务器建议的其它服务器。可以是空数组（=「我不知道别的服」，与 404 同效）。
  "servers": [
    {
      "name": "网友服 · nekotc",        // 必须：显示名，≤ 32 字符（= picker-core 的 NAME_MAX）
      "address": "https://sp.nekotc.cn", // 必须：地址，写法与玩家手填完全一样（见 §3）
      "note": "支持倍速",                // 可选：一句话备注，≤ 40 字符，纯文本
      "caps": ["skins"]                 // 可选：能力声明，见 §4。缺省 = 未知，不假设任何能力
    }
  ]
}
```

**宽容原则（照抄上游对 `room.ownership` / `room.diy` 的做法）**：服务端下发的内容是**第三方数据**，
客户端必须**逐条挑**，而不是整体接受或整体拒绝：

| 情况 | 客户端行为 |
|---|---|
| 顶层不是对象 / `v` 不是 1 | **整体忽略**，退回静态列表 |
| `servers` 不是数组 | **整体忽略** |
| 某条缺 `name` 或 `address`、或不是字符串 | **丢掉这一条**，其余照收 |
| 某条 `address` 过不了 `addressError()`（picker-core 既有的地址校验） | **丢掉这一条** |
| 某条 `address` 归一化后与玩家列表里已有的重复 | **丢掉这一条**（去重键见 §3） |
| `servers` 超过 50 条 | **只取前 50 条**（防一台服推上千条把选择页撑爆） |
| `caps` 里有不认识的字符串 | **忽略那个字符串**，不报错 |
| `name` 超长 | **截断到 32 字符**，不丢 |

> 一句话：**坏数据最多让你少一条服，不能让你选不了服。**

## 3. 地址与去重（与既有实现一字不差）

**地址写法**：与玩家在手填框里敲的**完全一样**。客户端已有的 `addressError()` → `toWsUrl()` 全套规则原样适用：

- 允许 `host` / `host:port` / `https://host/play` / `ws://host:port/ws`；
- 归一化用 **`toWsUrl`**（`js/net.js` 注入的那份，`picker.js:89` 已经在用）；
- 探测时仍然 `orderCandidates` **并发**试 `typed path / root × ws / wss` —— 所以清单里写
  `https://host/play` 还是 `https://host/` **都行**，客户端自己会试。建议服务器**下发它自己确认过的那个**。

**去重键**：`toWsUrl(address)` 归一化后的字符串（与 `missingSeeds` 的 `keyOfAddress` 一致）。
这条规则的意义：玩家**手填过** `sp.nekotc.cn`（或 `https://sp.nekotc.cn/`），
服务器再下发 `wss://sp.nekotc.cn/ws`，**不会变成两条**。

## 4. 能力声明 `caps` —— 「服务器各有服务特点，客户端要做多服务器兼容」

这是本接口的**核心增值**：网络里每台服都改了自己的代码（外援干员 / 倍速 / 匹配 / 官方 3D 素材 ……），
客户端不该假装它们一样。

### 4.1 已知能力值（本文版本 = 1 的完整集合）

| `caps` 值 | 含义 | 客户端据此做 |
|---|---|---|
| `skins` | 支持 `room.skins`（干员皮肤同步，我们 fork 的自研功能） | 有 → 皮肤对**队友**可见；没有 → 保持「仅自己可见」徽章 |
| `standins` | 支持 `room.ownership`（补位） | 显示补位相关 UI |
| `diy` | 支持 `room.diy`（自选编队） | 显示自选编队 UI |
| `spectate` | 支持观战席 | 显示「观战」按钮 |
| `bots` | 支持 `room.addBot` | 显示加电脑按钮 |

> ⚠️ **这张表是「客户端已经有 UI 的那个开关」的投影，不是实验性功能的许愿池。**
> 加一个新值 = 客户端必须先**真的有一处 UI 或行为**受它控制；否则加进来没有消费方，只会腐烂。

### 4.2 缺省与失败方向（**关键**）

```
caps 缺席  ⟹  「未知」  ⟹  客户端按「乐观放行」处理（与该能力相关的 UI 照常显示）
caps 为空数组 [] ⟹  「明确不支持任何扩展能力」
```

**这条和 `AGENTS.md` §5 的既有规矩完全一致**：

> 读不到（自建服没 CORS）= **unknown，一律乐观放行**，禁止把功能锁死；真正的权威是服务器那次拒绝本身。

也就是说：`caps` **只用于提前优化提示**，**绝不**用作准入闸门。没有 `skins` 的服务器照样能进，
只是进了之后客户端保持自己的本地皮肤（今天就是这样）。

### 4.3 服务端如何填

服务端**只声明自己确实实现了的**。`lilyco-42` 我们的服填 `["skins"]`。
**禁止**按「上游 0.2.1 可能有哪些」推测填充 —— 只写自己代码里真的接住了那个动词的。

## 5. 为什么必须回 CORS 头（这条最容易漏）

客户端有两种运行形态：

| 形态 | 页面源 | 请求 `https://sp.lain42.top/servers.json` |
|---|---|---|
| 浏览器直连网页 | `https://sp.lain42.top` | **同源**，本来就没问题 |
| 打包客户端（exe / apk / ipa） | `file://` 或 `http://127.0.0.1:47821` | **跨域** |

而客户端今天读 `/healthz` 的写法（`picker.js:163`）是：

> `// Best effort, never blocking: /healthz usually has no CORS headers, and that is the server's business.`

它用的是 **`no-cors` fetch** —— 能判断「对方活着」，但**读不到 body**。这够 `probeReason` 用，
**不够**读一份 JSON 清单。

所以 `/servers.json` **必须显式回 `Access-Control-Allow-Origin: *`**，否则打包客户端永远拉不到列表，
而且**失败是静默的**（fetch 只在控制台留一条 CORS 报错），排查起来很费时间。

> 若某台第三方服没有回 CORS 头 → 客户端**照常静默退回**（P1），不报错、不重试、不提示。
> 这不是我们的接口没写好，是那台服没实现（或实现漏了 CORS），属于预期内。

## 6. 客户端消费流程（在 `picker.js` 里，纯增量）

```
玩家选定 / 启动时选定一台服务器 S
        │
        ├─（后台、不阻塞、有超时）GET <S 的 http 根>/servers.json
        │     超时 3 s；任何失败（404 / 网络 / CORS / JSON 坏）→ 静默结束
        │
        └─ 成功 → 逐条按 §2.1 的宽容规则筛 → 与现有 K_LIST 按 §3 去重
                  → 把通过的**追加**进 K_LIST
                  → 名字**不覆盖**玩家改过的（与 seeding 同一套：只补缺、不动已有）
```

**必须满足的边界**：

1. **不阻塞进服**：拉取在后台进行，玩家该进游戏就进游戏。
2. **每次启动最多拉一次**：不轮询、不重试（避免把一台刚关的服变成 3 s 的卡顿源）。
3. **不写 `K_SEED`**：这是**与静态播种独立的第二条通道**。静态播种的「删了不回来」语义由 `K_SEED` 保证；
   动态拉取天然每次都可能带回旧条目 —— 所以：
   - **动态拉取的条目也必须可删**，且**玩家删掉后，本次安装不再被同一条目打扰**。
   - 实现上追加一个**已忽略集**（`sp.shell.dismissed`，存 `toWsUrl` 归一化键），
     删除条目时写入它，拉取时跳过。静态播种**不**受它影响（`K_SEED` 的语义原样保留）。

> ⚠️ 第 3 条是本方案**唯一新增的存储键**。它必须有自己的变异测试（见 `agents/server-list/agent.md` §3），
> 否则「删了又回来」会成为一个玩家会立刻发现、而测试抓不到的 bug。

## 7. 备选方案与为什么不选

| 方案 | 结论 |
|---|---|
| `/api/servers` 前缀 | ❌ 上游没有 `/api/` 命名空间（只有 `/healthz`、`/assets`、`/packs`）。自造一个会让日志、反代规则、文档都多一层无谓的分叉。 |
| 塞进 `/healthz` 的一个新字段 | ❌ `/healthz` 是**探活**端点，被 `buildGuard` 每 60 s 打一次、被 `probeOnce` 每次探测打一次。往里加一份可变的清单 = 让一个高频小响应变重，且语义混淆（探活 vs 发现）。 |
| 走 WebSocket 新动词（如 `servers.list`） | ❌ 需要在 `shared/protocol.js` 加动词 → 那要改**游戏本体**的协议表，且旧服务器回 `BAD_MSG` 时要多一条降级路径。HTTP 一条直路更短，且**能在没进游戏之前**就问。 |
| 客户端内置一份「中央列表」URL | ❌ 单点。而且那台「中央服」一关，全网客户端都卡在超时上。**每台服各自回答**没有这个单点。 |
| 用 DNS TXT / 一个公共 gist | ❌ 引入外部依赖（`AGENTS.md` §6 的产物闸门要求零外部请求），且第三方平台随时改政策。 |

## 8. 服务端实现落点（游戏本体 fork）

**不改上游文件的行为**：在 `server/http/static.js` 的 `serveStatic` 里加一段，
与既有的 `/packs/index.json` 特判**完全同构**（`sendJson(req, res, 200, payload)` + 从不缓存）。

- **内容来源**：一个**可选的**数据文件（如 `data/servers.json`），不存在 → **404**（P1）。
  这样：① 我们的服放一份就生效；② 上游/别人不放就自动退回今天的行为；③ **零配置、零环境变量**。
- **CORS**：只在这一个端点的响应上加 `Access-Control-Allow-Origin: *`（用 `sendJson` 之后补一个
  `setHeader`，或本端点自带一个带头的 `sendJson` 变体；**不要**给 `/healthz` 或静态文件全局加，那会扩大面）。
- **`caps` 由服务端自己写死在配置里**，不从环境变量猜。

> 该端点**只读**、**无状态**、**不碰内存**（不像 `/healthz` 要读 `lobby.stats()`），
> 对那台 1682 MB / 2 核的 ECS **零额外负担**。

## 9. 上线与验证（"什么算证据"）

沿用 `AGENTS.md` §6：

1. **接口级**：`curl -i https://sp.lain42.top/servers.json` → `200` + `Content-Type: application/json`
   + `Access-Control-Allow-Origin: *` + `Cache-Control: no-store`。
2. **无配置时的降级**：临时移走 `data/servers.json` → 必须 **404**（不是 500、不是空对象）。
3. **跨域实测**：从 `file://` 打开的页面里 `fetch(...)`，**必须读到 body**（不是 `TypeError: Failed to fetch`）。
4. **客户端全链路**：真实页面里点出来 —— 拉到的条目**出现在选择页**、**可删**、**删了重启不再回来**。
5. **回归**：目标服不实现该接口 → 客户端行为与今天逐字节一致（`npm test` 不低于开工前实测基线）。

## 10. 版本演进

- `v` 是**格式版本**，不是协议版本（与 `PROTOCOL_VERSION` 无关）。
- 加**可选字段** = 不升 `v`（客户端本来就要宽容）。
- 改已有字段的含义 / 删字段 = **升 `v`**。客户端见到不认识的 `v` 就整体忽略（回到静态列表），
  而不是尝试解析 —— 这是唯一能防止「新旧互相读错」的做法。
